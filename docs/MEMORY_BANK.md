# 记忆库（Memory Bank）

让 PokeClaw 跨会话记住用户：身份、偏好、设备与账号事实、踩过的坑、重要任务的结果。

记忆库和知识库（`kb_*` 工具 / `vault/` markdown 金库）是两套东西：

| | 知识库 KB | 记忆库 Memory Bank |
|---|---|---|
| 内容 | 用户自己写的文档、笔记、待办 | 模型自己判断值得长期记住的一句话 |
| 工具 | `kb_write` / `kb_read` / `kb_search` / `kb_append` / `kb_add_todo` | `memory_save` / `memory_recall` / `memory_forget` |
| 存储 | `files/vault/**/*.md` | `files/memories.json` |
| 谁调用 | 用户主动让 Agent 记东西 | Agent 自主调用 + 用户在管理页校对 |
| 进入上下文 | 模型自己 `kb_read` 时 | 每个任务自动注入系统提示 |

## 自动注入

`DefaultAgentService.runAgentLoop` 在拼系统提示时追加 `MemoryStore.briefing(当前任务文本)`：
按与当前任务的相关性挑最多 12 条（总长约 1400 字符），置顶条目必进。注入的小节同时把三条
记忆工具的用法讲给模型听，所以记忆库为空时模型也知道该记什么。

排序不用向量，纯本地打分：

```
score = 类型权重(身份1.2 / 偏好1.0 / 事实0.7 / 事件0.3)
      + 置顶 3.0
      + 与当前任务词元重合 +2.0（标签命中再加）
      + 2.0 × 保留度(entry)                  // 见下节
```

中文靠二元组（bigram）切词，不需要分词器；英文按 ≥2 字符的词。`memory_recall` 命中的条目
`hits+1` 并刷新 `lastUsedAt`——"被用得多"这件事只由下面的保留度曲线表达，打分里没有单独的
命中次数项（`hits` 和 `lastUsedAt` 永远一起涨，算两遍就是把同一个信号奖励两次）。

## 保留度（access-weighted retention）

`MemoryRetention`：一条记忆**还值不值得注入**，一条独立的曲线，不属于排序公式。改排序权重时
它不动，它自己回答的是另一个问题。三个用途：排序里的衰减项、超过 200 条时的淘汰顺序、管理页
上看得见的"渐淡"标记。

```
保留度 = exp(−闲置天数 / 半衰期)
半衰期 = 14 × (1 + log₂(1 + hits)) 天，上限 365 天
闲置天数 = 距上次被召回的天数（从未召回则从最后编辑时间算）
```

三条设计取舍：

- **指数，不是线性。** 原来那项是 `max(0, 1.5 − 0.04 × 天数)`，到 37.5 天正好归零并永远归零——
  一条被召回过三十次的和一条从没被碰过的死在同一个时钟上。指数没有地板：好用的记忆永远留一小份
  权重，没用过的迅速淡出。
- **对数，不是线性加分。** 每翻一倍 `hits` 加固定 14 天。第十次命中的价值必须低于第一次，否则
  一条被反复召回的记忆可以自己买到永生。365 天的上限是为此留的兜底。
- **保留度永不删除。** 淡出只是不再注入，条目还在库里。真按衰减清理会有严重副作用：每次删除
  都留抑制指纹，被清理掉的条目和"用户让忘掉的那条"在数据上无法区分，Agent 会被永久禁止
  再学会它。**记忆是被使用淘汰出提示词的，只有用户能把它淘汰出记忆库。**

时钟锚点是"上次被召回"而不是创建时间：半年前写下、昨天召回过的记忆是新鲜的。召回信号也来自
`hits` 与 `lastUsedAt` 的联动——Agent 重新学到同一件事（合并时两个字段一起刷新）算作再确认，
不算陈旧。`lastUsedAt` 来自可手改的 JSON，时间戳写到未来会被夹到 0 闲置，不白送保留度。

管理页列表尾部只标**淡的那一截**（渐淡 / 几乎遗忘），页脚汇总"N 条渐淡"。稳的那部分不标——
标了就是噪音；而且一条默默不再生效的衰减曲线，和一条正常工作的衰减曲线看起来一模一样。

## 去重合并

同一件事会在不同会话里被重新学到，只是措辞略有差别。不合并的话简报会被近义重复塞满，
模型开始自相矛盾。所以 `remember()` 先归一化（去空白、转小写），若新旧互为子串就合并：
取更长的一条、标签取并集、`hits+1`、置顶取或。

## 矛盾暴露

新事实如果"框架不变、只换了值"，不会被静默地堆在旧事实旁边——两条都会被标记，工具
返回值和管理页都会带 ⚠，注入简报时也会提示模型"不能只凭一条回答，应直接问用户"。

判定三条规则，宁可漏报也不误报（误报会让 Agent 拿无冲突的事盘问用户，比漏报更糟）：

| 规则 | 例子 |
|---|---|
| 骨架相同、数字/日期/引号内容不同 | 用户每周跑3次 → 每周跑5次 |
| 骨架相近、极性翻转（一边有否定词） | 用户喜欢用微信 → 用户不喜欢用微信 |
| 长前缀相同、末尾短槽位被换掉（且不是"延长"） | 用户在杭州出差 → 用户在上海出差 |

用的是 `MemorySimilarity.contradicts()`，纯词法：CJK 二元组 + 数字/引号提取，没有模型，
`MemorySimilarityTest`（20 个用例）锁住行为，包括"必须不触发"的那几条。

**已知边界**：改述式矛盾（"不喜欢被工作打扰" vs "不希望晚上被工作消息找"）召不出来，
因为词法匹配看不见同义。

## 遗忘抑制（指纹）

删除一条记忆时，除了删掉条目，还把它写进 `memory_suppressions.json` 留一枚指纹。
之后 `memory_save` 写入的内容若落在任意一枚指纹下，直接拒绝并把被删除的原文回给
模型——**遗忘是抑制，不是删除**。否则同一件事会在几轮对话后被重新学回来，用户根本
没要求过。

判定用两把尺子，缺一把都会漏：

| 尺子 | 命中什么 | 漏了什么 |
|---|---|---|
| bigram Dice ≥ 0.7 | 原句、轻微改写 | 换了值 |
| 句子骨架冲突（复用矛盾判定） | 同一个说法换了值 | 整句改写 |

只留第一把尺子时，实测漏得最狠的两组正好都是"换个值再说一遍"：

```
用户的手机是Pixel  →  用户的手机是小米    Dice 0.59   旧版漏掉
用户每周跑3次      →  用户每周跑5次      Dice 0.67   旧版漏掉
用户每周跑3次      →  用户每周跑步3次    Dice 0.77   靠措辞兜住
```

Agent 不会把你让它删掉的那句话原样背回来，它会把**同一个主张换个值**再存一遍。
骨架判定按句式而非措辞匹配，正好接住这三组里的前两组。

三个豁免：

- 用户在管理页手动添加记忆**不受抑制**——明确的人为动作高于指纹（否则"删错了想加回来"会变成死路）。
- 抑制判定排在合并判定**之前**：否则一条碰巧和别的记忆重叠的旧事实会被悄悄合并回去，
  正好是抑制要防的那件事。
- 管理页「遗忘抑制」里可以**逐条**解除或恢复，也可以整体清除。逐条是必要的：
  只有"全部清除"的话，删错一条就等于把整本抑制账本交出去。

## 值得借鉴的：akitaonrails/ai-memory

这个仓库（Rust）解决的痛点比记忆库大得多——跨 agent、跨项目、跨机器共享记忆，
明面上的记忆就是一堆 git 托管的 `.md`，数据库只是可重建的索引。但它的三条设计
值得抄：

1. **软删除，不是硬删**——原文留在版本链里，`restore-page` 随时捞回来。我们对应的是
   指纹里的原文 + 逐条恢复。
2. **指纹可见，不只是计数**——一个数字说明不了"现在到底挡住了什么"，一个正常工作的
   抑制和一个在偷偷吃掉正常记忆的抑制，看起来长得一模一样。所以管理页直接列出每枚
   指纹的原文、分类、挡过几次。
3. **矛盾标记走零 LLM 路径**——它的 contradiction/dedup/decay 全是规则算出来的。
   这和我们"宁可漏报不误报"的取舍是同一个判断。

它的分层保留（access-weighted retention：被用过的记忆衰减更慢）我们已经补上了独立的
`MemoryRetention` 曲线，见上节。它的 `decay` 是零 LLM 的规则算出来的，和我们"宁可漏报不误报"
是同一个判断。

## 分类

| kind | 中文 | 什么时候用 |
|---|---|---|
| `profile` | 身份 | 姓名、学校、专业、长期身份 |
| `preference` | 偏好 | 习惯、禁忌、语言与风格要求 |
| `fact` | 事实 | 设备、账号、环境上的稳定事实 |
| `event` | 事件 | 发生过、以后还会影响判断的事 |

## 文件格式

`memories.json`，外部文件目录，可用 `adb push` 直接播种或手改：

```json
[
  {
    "id": "seed0000001",
    "content": "用户是示例大学计算机专业的大二学生。",
    "kind": "profile",
    "tags": ["用户", "身份", "学校"],
    "pinned": true,
    "createdAt": 1788000000000,
    "updatedAt": 1788000000000,
    "hits": 0,
    "lastUsedAt": 0
  }
]
```

解析逐字段容错：缺字段、类型写错、缺 `content` 的条目都会被丢掉或退回默认值，不会整库报废。
上限 200 条，超了按「非置顶、保留度低、久未更新」依次淘汰——用保留度而不是原始 `hits`，
因为光看命中次数分不出"命中很多但很久没用了"和"最近才写的新记忆"。

**淘汰和删除是两回事**：淘汰只是把条目从库里挤出去（真的会从 `memories.json` 消失），
但**不留抑制指纹**，所以 Agent 之后重新学到同一件事是允许的；而用户主动删除一定留指纹。
容量不够不是"用户不要这条了"的证据，反过来才是。

字段没有变化：保留度完全由已有的 `hits` / `lastUsedAt` 算出，不新增 JSON 键，
所以 `adb push` 播种和旧文件都不受影响。

```bash
adb push memories.example.json \
  /sdcard/Android/data/io.agents.pokeclaw/files/memories.json
adb shell am force-stop io.agents.pokeclaw   # 重启后重新读取
```

## 管理界面

设置 → 工具 → 记忆库（`ui/settings/MemoryActivity`）：搜索、按类排序、点击编辑、长按删除、
手动添加、导出 Markdown、总开关。带 ⚠ 的条目是互相矛盾的一对，带「渐淡 / 几乎遗忘」的条目
是保留度已经掉下去的（见上节）。

「遗忘抑制（N）」点开是**指纹列表**，不是清空按钮——每条显示原文、分类、挡过几次，
可选「恢复记忆」（放回记忆库并解除抑制）或「仅解除抑制」（只让 Agent 可以重新学到）。
列表右上角的「全部清除」才是旧的一键清空。

**总开关关掉后**：不再向模型注入任何记忆，`memory_save` 也会明确回复"没有保存"，但库里已有的
条目保留，随时可以再打开。
